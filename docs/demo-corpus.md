# Demo Corpus

## Назначение

Этот файл фиксирует минимальный демонстрационный набор документов для защиты.

Demo-corpus должен быть:

- небольшим;
- понятным комиссии;
- воспроизводимым;
- пригодным для показа реальных изменений между редакциями;
- безопасным для локальной демонстрации.

## Принцип подбора

Для защиты лучше использовать не «много документов», а **2–3 понятных кейса**, в которых легко показать прикладную ценность.

Предпочтительные типы изменений:

1. изменение сроков предоставления услуги;
2. изменение перечня документов;
3. изменение обязанностей или порядка действий сотрудника;
4. изменение оснований отказа;
5. редакционные изменения, которые можно показать как менее значимые.

## Рекомендуемый состав

### 1. Базовый обязательный кейс

**Документ:** административный регламент / внутренний регламент приёма заявлений

**Пара версий:**
- v1 — старая редакция;
- v2 — новая редакция.

**Что должно измениться:**
- срок выполнения услуги;
- список документов;
- формулировка основания отказа.

**Зачем нужен:**
- это лучший кейс для показа полного маршрута `compare → brief → quiz → report`.

### 2. Кейc на обязанности сотрудника

**Документ:** порядок взаимодействия сотрудника с заявителем

**Пара версий:**
- v1 — старая редакция;
- v2 — новая редакция.

**Что должно измениться:**
- обязанность проверить новый реквизит;
- новый порядок уведомления;
- перенос одного пункта в другую часть документа.

**Зачем нужен:**
- позволяет показать modified и moved;
- хорошо объясняет практическую пользу для сотрудников.

### 3. Кейс на редакционные изменения

**Документ:** служебный регламент / инструкция

**Пара версий:**
- v1;
- v2.

**Что должно измениться:**
- несколько редакционных правок;
- одна содержательная правка.

**Зачем нужен:**
- показывает, что система различает важные и менее важные изменения;
- полезен для ответа на вопросы комиссии.

## Что должно быть предзагружено

Перед защитой рекомендуется заранее загрузить:

- все demo-документы и версии;
- минимум один уже утверждённый тест;
- минимум одну сохранённую попытку прохождения;
- минимум один отчёт, который уже можно открыть.

## Команда подготовки

```bash
python manage.py load_demo_pairs
```

Эта команда должна использоваться как стандартный способ восстановления демонстрационного набора перед прогоном защиты.

# Notes

## 2026-03-17 — фиксация решений базового контура

### 1. Зафиксированная формулировка проекта

**Интеллектуальная система анализа нормативно-правовых документов, обеспечивающая выявление значимых изменений, генерацию кратких разъяснений и формирование тестовых материалов для проверки знаний сотрудников.**

### 2. Главный прикладной сценарий

**документ → версии → изменения → выжимка → генерация теста → утверждение → прохождение → отчёт**

### 3. Главный режим анализа

**сравнение новой редакции документа с предыдущей редакцией того же документа**

### 4. Управляющие архитектурные решения

- local-first;
- backend-first;
- deterministic / hybrid first;
- explainability важнее «магии»;
- demo-ready важнее функционального разрастания.

## 2026-03-19 — решения этапа стабилизации

### 1. Что зафиксировано по факту аудита

Подтверждено, что в коде уже есть:
- ingestion pipeline;
- compare / brief / quiz flow;
- approval и attempt flow;
- demo UI;
- demo corpus;
- backend test suite.

### 2. Что было признано важными ограничениями

- PDF поддерживается только при наличии текстового слоя;
- search/Qdrant является опциональным слоем;
- demo UI не следует описывать как полноценный продуктовый интерфейс;
- auth и развитая ролевая модель остаются вне раннего scope.

### 3. Решения по воспроизводимости запуска

Принято:
- локально по умолчанию использовать SQLite;
- в docker-compose явно использовать PostgreSQL;
- не ожидать Postgres в entrypoint, если выбран SQLite;
- не считать Qdrant обязательным сервисом базового запуска.

### 4. Решения по тестовому контракту

Принято считать корректным поведение:
- квиз в статусе `draft` нельзя выдавать сотруднику;
- попытка прохождения разрешена только для `approved` квиза;
- тесты должны проверять именно этот контракт.

### 5. Решения по документации

Принято:
- развести функциональные фазы проекта и текущий инженерный этап стабилизации;
- не обозначать поздние фазы как полностью завершённые, если они ещё требуют полировки;
- описывать runtime-контур и ограничения проекта честно и без завышения готовности.

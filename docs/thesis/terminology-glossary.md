# Terminology Glossary for Chapters 1–3

| Термин | Рекомендуемое употребление | Комментарий |
|---|---|---|
| интеллектуальная информационная система | локальная интеллектуальная информационная система анализа изменений документов | Употреблять как обозначение разработанной системы. Не называть систему юридической экспертной системой, универсальным чат-ботом, LMS или СЭД общего назначения. |
| нормативно-правовой документ | нормативно-правовой документ | Использовать для внешних правовых и нормативных документов. При необходимости в финальной редакции можно уточнить различие с нормативно-правовыми актами. |
| внутренний регламентный документ | внутренний регламентный документ | Использовать для локальных положений, инструкций, административных регламентов и внутренних процедур организации. |
| редакция документа | редакция документа / версия документа | В академическом тексте предпочтительно «редакция»; при связи с моделью данных допустимо «версия документа». |
| DocumentVersion | `DocumentVersion` | Название ORM-сущности оставлять в backticks. В обычном тексте пояснять как конкретную редакцию документа. |
| extraction | extraction / извлечение текста | Первое употребление: «extraction — извлечение текста из файла документа». Соответствует этапу `E`. |
| normalization | normalization / нормализация текста | Первое употребление: «normalization — безопасная нормализация текстового представления». Соответствует этапу `N`. |
| structural chunking | structural chunking / структурное разбиение | Использовать единообразно вместо хаотичного `segmentation`, если речь идёт о методе проекта. Соответствует этапу `S`. |
| structural chunk | структурный фрагмент / `Chunk` | В академическом тексте — «структурный фрагмент»; при связи с моделью данных — `Chunk`. |
| path_key | `path_key` | Технический устойчивый структурный ключ внутри версии документа. Не описывать как глобальный юридический идентификатор. |
| comparison / diff | comparison / сравнение редакций; diff — технический результат сравнения | Для этапа метода использовать `comparison` или «сравнение редакций». `diff` оставлять для технических отличий, baseline-сравнений и payload. |
| change item | change item / `VersionChangeItem` / материализованное изменение | Употреблять как единицу результата comparison. В русском тексте можно использовать «материализованное изменение». |
| significance-layer | significance-layer / слой оценки значимости | Использовать «значимость», а не смешивать с «важностью» без необходимости. Соответствует этапу `P`. |
| summary-layer | summary-layer / слой формирования человеко-читаемой выжимки | Предпочтительно «человеко-читаемая выжимка» или `summary`. Не называть юридическим заключением. |
| quiz generation | quiz generation / генерация контрольно-обучающих материалов | В академическом тексте связывать с проверкой усвоения изменений. Не утверждать, что вопросы всегда корректны без approval. |
| human-in-the-loop | human-in-the-loop / участие ответственного лица | Использовать для approval workflow и экспертной проверки. Это обязательное ограничение нормативной области. |
| materialized artifact | материализованный артефакт | Употреблять для сохранённых промежуточных результатов: chunks, comparison, change items, summary, quiz, attempts. |
| evaluation corpus | evaluation corpus / корпус экспериментальной оценки | Отделять от demo corpus. Подчёркивать synthetic/small-scale характер и ограничение выводов. |
| demo corpus | demo corpus / демонстрационный корпус | Использовать только для данных демонстрационного сценария, не смешивать с корпусом расчёта метрик. |
| key-change annotation | key-change annotation / разметка ключевых изменений | Не описывать как полный юридический gold standard. Использовать при интерпретации метрик главы 3. |
| local-first architecture | local-first архитектура / локальная воспроизводимая архитектура | Подчёркивает независимость базового pipeline от облачных сервисов и обязательной LLM. |
| deterministic/rule-based baseline | deterministic/rule-based baseline / детерминированный baseline | Использовать для structural chunking, significance-layer и quiz generation там, где речь идёт об эвристиках MVP. Не выдавать baseline за окончательную экспертную систему. |

## Термины, требующие особой унификации

- `comparison` / `diff`: этап метода называется comparison / сравнение редакций; `diff` — технический результат или baseline-подход.
- `significance` / `importance`: в главах использовать «значимость» и `significance-layer`; `importance` допустим только при ссылке на старые поля/артефакты, если они так названы в коде или JSON.
- `summary` / «выжимка»: предпочтительно «человеко-читаемая выжимка»; не использовать как синоним юридического заключения.
- `quiz` / «тест»: в научном тексте предпочтительно «контрольно-обучающие материалы» или `generated quiz`; подчёркивать обязательность approval workflow.

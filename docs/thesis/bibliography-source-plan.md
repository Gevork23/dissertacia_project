# Bibliography Source Plan

## 1. Какие типы источников нужны

Для финальной версии диссертации нужны только реальные и проверяемые источники:

- научные статьи и обзоры по электронному документообороту, document management systems и ECM;
- статьи и технические обзоры по diff algorithms, document comparison и structure-aware comparison;
- обзоры и прикладные работы по legal NLP, legal document processing и document intelligence;
- исследования по LLM hallucinations, reliability, grounded generation и traceability;
- источники по human-in-the-loop systems, responsible AI и AI-assisted decision support;
- источники по compliance training, employee learning и контролю усвоения изменений;
- методологические источники по evaluation methodology, precision/recall/F1, rubric evaluation, threats to validity и reproducibility;
- официальная документация или стандарты, если они используются для описания СЭД, правовых систем или требований к оформлению.

## 2. Приоритетные категории источников

1. **Document comparison / diff / structure-aware comparison** — необходимы для обоснования выбора structural chunk diff и сравнения с baselines.
2. **Legal NLP / document intelligence** — нужны для позиционирования задачи обработки нормативных и регламентных текстов.
3. **LLM reliability / hallucinations / grounding** — нужны для осторожного описания optional LLM и рисков unsupported claims.
4. **Human-in-the-loop / responsible AI** — нужны для обоснования approval workflow.
5. **Evaluation methodology** — нужна для защиты synthetic corpus, key-change annotation и threats to validity.
6. **DMS / ECM / электронный документооборот** — нужны для введения и главы 1.
7. **Compliance learning / employee training** — нужны для обоснования связки summary/quiz/result.

## 3. Где искать источники

Рекомендуемые площадки поиска на следующем этапе:

- Google Scholar;
- IEEE Xplore;
- ACM Digital Library;
- SpringerLink;
- ScienceDirect;
- arXiv для свежих работ по LLM reliability и document intelligence с последующей проверкой качества;
- официальные сайты стандартов, вендоров или регуляторов, если нужны нормативные / отраслевые определения;
- eLIBRARY / КиберЛенинка для русскоязычных источников по СЭД, электронному документообороту и регламентам;
- документация типовых систем или официальные white papers только как вспомогательные источники, не как замена научным публикациям.

## 4. Какие утверждения должны быть подкреплены

Источниками должны быть подкреплены утверждения о том, что:

- объём нормативной информации и электронного документооборота растёт;
- DMS / ECM / СЭД решают задачи хранения, маршрутизации и версионирования документов;
- простые diff-подходы ограничены при анализе структурированных документов;
- юридические и регламентные тексты требуют учёта структуры и контекста;
- legal NLP / document intelligence применяются к юридическим документам, но требуют разметки и оценки качества;
- LLM могут генерировать unsupported claims и требуют grounding / traceability;
- human-in-the-loop review важен для AI-assisted систем в ответственных областях;
- автоматические учебные материалы и вопросы требуют проверки качества;
- synthetic evaluation и key-change annotation ограничивают внешнюю валидность;
- threats to validity являются обязательной частью корректной экспериментальной интерпретации.

## 5. Минимальный набор источников перед сдачей

Минимально желательно закрыть следующие блоки:

| Категория | Минимум источников | Назначение |
|---|---:|---|
| Электронный документооборот / DMS / ECM | 2–3 | Введение, глава 1 |
| Document comparison / diff algorithms | 3–4 | Глава 1, глава 2, сравнение baselines |
| Legal NLP / document intelligence | 3–4 | Глава 1 и позиционирование метода |
| LLM hallucinations / reliability / grounding | 2–3 | Ограничения optional LLM и summary risks |
| Human-in-the-loop / responsible AI | 2–3 | Approval workflow и safety framing |
| Compliance learning / employee training | 1–2 | Обоснование summary/quiz/result contour |
| Evaluation methodology / threats to validity | 3–4 | Глава 3, ограничения эксперимента |

Итого минимальный ориентир: около 16–23 проверяемых источников до финальной сдачи. Точное число должно соответствовать требованиям кафедры и рекомендациям научного руководителя.

## 6. Источники, которые нельзя выдумывать

Нельзя выдумывать:

- авторов, названия статей и журналов;
- DOI, ISBN, URL и даты обращения;
- ГОСТ-оформление несуществующих публикаций;
- ссылки на стандарты, если стандарт не был реально проверен;
- статистические отчёты о документообороте без реального источника;
- утверждения вида «в исследованиях доказано», если конкретные исследования не найдены.

Если утверждение не удаётся подкрепить, его нужно либо ослабить, либо оформить как ограниченное наблюдение / проектную мотивацию.

## 7. План дальнейшей работы с библиографией

1. Выписать все placeholders и тезисы из `bibliography-gap-analysis.md`.
2. Для каждой категории подобрать реальные источники, начиная с high-priority тезисов.
3. Проверить, что источник действительно подтверждает конкретное утверждение, а не просто относится к теме.
4. Сохранить полные библиографические данные: авторы, название, год, издание, DOI/URL, дата обращения для интернет-источников.
5. Заменить placeholders в тексте на ссылки в выбранном стиле.
6. Сформировать список литературы по требованиям кафедры / ГОСТ.
7. Проверить соответствие всех внутритекстовых ссылок записям списка литературы.
8. После согласования с научным руководителем удалить из финального текста все editor placeholders.

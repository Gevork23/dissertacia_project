# ROADMAP

## Общая логика проекта

Проект развивается не как набор разрозненных AI-функций, а как прикладная система с чётким маршрутом:

**документ → версии → изменения → выжимка → тест → прохождение → отчёт**

Ниже зафиксированы фазы проекта от 0 до 6.

---

## Фаза 0. Фиксация замысла проекта

### Цель
Убрать туман и зафиксировать единое понимание проекта.

### Что должно быть на выходе
- понятное описание проекта;
- единая формулировка цели;
- понятный основной сценарий;
- границы MVP;
- архитектурные принципы;
- roadmap и tasks;
- согласованная документация.

### Definition of Done
- документация не противоречит сама себе;
- можно кратко объяснить проект в 1–2 абзацах;
- все участники одинаково понимают, что делаем и что не делаем.

---

## Фаза 1. База: документы, версии, парсинг

### Цель
Сделать устойчивую основу для загрузки и хранения документов.

### Что делаем
- модели документов и версий;
- загрузку файлов;
- поддержку DOCX / PDF / TXT;
- извлечение текста;
- нормализацию текста;
- разбиение на структурные блоки.

### Definition of Done
- можно загрузить документ и новую редакцию;
- текст извлекается стабильно;
- структура документа разбивается воспроизводимо;
- есть тесты на ingestion.

---

## Фаза 2. Сравнение редакций

### Цель
Сделать надёжное сравнение новой и предыдущей версии.

### Что делаем
- diff по структурным фрагментам;
- added / removed / modified / moved;
- выделение значимых изменений;
- объяснимую классификацию изменений.

### Definition of Done
- система корректно сравнивает две версии одного документа;
- результат сравнения пригоден для дальнейшей выжимки и тестов;
- есть тесты на ключевые сценарии.

---

## Фаза 3. Выжимка и генерация теста

### Цель
Сделать из изменений понятный обучающий материал.

### Что делаем
- краткую выжимку;
- генерацию тестовых вопросов по diff;
- сохранение теста;
- подготовку теста к проверке ответственным лицом.

### Definition of Done
- по двум версиям можно получить краткое описание изменений;
- по изменениям можно сгенерировать тест;
- тест основан на конкретных изменениях, а не на абстрактных знаниях.

---

## Фаза 4. Утверждение, прохождение, результаты

### Цель
Замкнуть пользовательский цикл.

### Что делаем
- утверждение теста ответственным лицом;
- прохождение теста сотрудником с указанием ФИО;
- сохранение результатов;
- отчёты.

### Definition of Done
- тест нельзя выдать без утверждения;
- сотрудник может пройти тест;
- результаты сохраняются;
- отчёт можно показать комиссии.

---

## Фаза 5. Демонстрационный MVP

### Цель
Собрать законченную прикладную систему для живой демонстрации.

### Что делаем
- минимальный UI;
- демонстрационный набор документов;
- воспроизводимый сценарий;
- стабилизацию запуска;
- расширение тестов;
- чистку лишних функций.

### Definition of Done
- MVP можно запустить на одном ПК;
- система открывается по сети;
- демонстрация проходит по шагам без ручных подправлений.

---

## Фаза 6. Подготовка к защите

### Цель
Довести проект до состояния, удобного для защиты и показа.

### Что делаем
- финальную полировку интерфейса;
- финальные диаграммы;
- финальный demo-script;
- описание практической значимости;
- финальные прогоны демонстрации.

### Definition of Done
- проект готов к защите;
- сценарий показа стабилен;
- документация, архитектура и демонстрация согласованы.

---

## Принцип планирования

Если новая задача не усиливает:

- сравнение версий;
- выжимку;
- генерацию теста;
- прохождение теста;
- отчёт;
- демонстрацию проекта,

то она не должна ломать roadmap и переносится за пределы MVP.
